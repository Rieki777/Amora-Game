# Amora Platform Audit — Final Report

## 1. Executive Summary

The platform is **functional but not yet production-hardened**. The audit surfaced no unauthenticated remote-code-execution or database-wide compromise, and the core economy invariants (conservation, illegal-negative guards) largely hold. However, there is a meaningful cluster of **exploitable security and economy defects** and a **broad, systemic accessibility gap**, so the honest verdict is: *solid bones, several sharp edges that need attention before scale.*

**Counts (42 findings adjudicated; 3 REFUTED + 1 downgraded-to-none excluded):**

| Verdict | High | Medium | Low | Total |
|---|---|---|---|---|
| CONFIRMED | 7 | 14 | 11 | **32** |
| PLAUSIBLE (PARTIAL) | 0 | 0 | 6 | **6** |
| **Survivors** | **7** | **14** | **17** | **38** |

*(Refuted/dropped: password-reset tokenVersion, badges URL-encode, push_subscriptions retention, base-reads user_id logging.)*

**Systemic themes** (these matter more than any single line):

1. **The wrong localStorage token key (`"token"` vs canonical `"amora-auth-token"`)** is a repeated one-character class of bug that silently breaks whole features for signed-in users: notifications (high), members/preview modules (high), tools visibility (medium), and account-deletion cleanup (low). One fix pattern clears four findings.
2. **Payment/webhook paths fail open and under-assert.** The Stripe webhook skips verification when the secret is unset, and the settle handlers never check `payment_status`/amount — a fail-safe-defense weakness feeding both a security and an economy finding.
3. **Accessibility is broadly unmet.** Zero programmatic label associations app-wide, no ARIA live regions, icon-only buttons, a keyboard-inoperable SVG map, and sub-40px tap targets — multiple WCAG Level A failures spanning every form.
4. **Account deletion is incomplete (Law 8968 posture).** Several member-linked tables (skill_tags, free-text messages, onchain cache, ledger label) survive anonymization, and the data-export claims completeness it doesn't deliver.
5. **Write buttons lack in-flight guards** (Forum, Feed, VillageMap) and client inputs lack clamping — double-submit and validate-after-click patterns throughout, mostly caught server-side but poor UX.
6. **Internal consoles aren't responsive** (fixed 224px sidebars on Admin and JourneyToLaunch break phones) — real but internal-audience, hence downgraded.

## 3. Fix Now vs. Defer

### Fix now — small, high-value, low-risk (do this session)
- **The token-key swap (biggest ROI on the board):** `NotificationBell.tsx:27,57`, `ModuleProvider.tsx:43`, `ToolsHub.tsx:52`, `NotifyPrefsPanel.tsx:94` → use `authToken()`. Four findings (two **high**), each a one-line change, no behavioral risk.
- **Stripe webhook fail-closed + settle assertions** (`payments.ts:175`): a few lines (`if (!secret) return 400`; assert `payment_status==='paid'` and amount). High security value, additive guard, low regression risk.
- **`/api/uploads` header hardening** (`index.ts:6144`): add `X-Content-Type-Options: nosniff` + `Content-Disposition: attachment` for non-image types. Closes the XSS execution path immediately (magic-byte sniffing can follow later).
- **Balance-inflation** (`index.ts:5711`): delete the `recognitionBalance +=` mutation. Small, removes a self-service integrity hole.
- **Profile bio** (`Profile.tsx:150`): wire `updateProfile` or remove the control — stops silent data loss.
- **Quick UX/a11y one-liners:** Stay nights clamp, Library empty-state, Gratitude zero-budget disable, hamburger `aria-label`+`aria-expanded`, `htmlFor`/`id` on the Login/Register/SetPassword forms, Forum/Feed/VillageMap in-flight `disabled` guards.

### Defer — larger, riskier, or policy-dependent (follow-up)
- **X-Forwarded-For / trust-proxy** (`index.ts:1779`): getting the Railway hop count wrong can lock out real users; needs config + testing.
- **Bootstrap default secret** (`index.ts:233`): couples to deploy config; needs a boot-refusal policy.
- **Stays refund double-clawback** (`index.ts:3988`) and **mint-cap TOCTOU** (`index.ts:5429`): economy correctness requiring idempotency-key/transaction rework and careful ledger testing.
- **Cycle-pool Sybil weighting** (`index.ts:6981`): change to `settleCycle`, needs economy validation.
- **reserveItem transaction wrap** (`library.ts:263`): DB-transaction refactor.
- **Anonymization completeness** (skill_tags, free text, onchain cache, ledger label) + **export completeness** (`index.ts:7399`): need one coherent Law-8968 retention/erasure policy decision, then implement together.
- **Full accessibility pass:** ARIA live regions systemic (route through sonner), all 151 admin form labels, VillageMap keyboard/focus rework.
- **Mobile responsive layouts** for Admin and JourneyToLaunch consoles (internal audience, so not urgent).
