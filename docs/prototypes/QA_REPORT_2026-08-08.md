**Build tested:** `game-amora/docs/prototypes/grounds-v0.html`, 4,653,984 bytes, mtime 2026-08-08 14:28 UTC (the 4.4 MB build with satellite + painted plates and 28 sprites).
**Harness:** Playwright 1.56 / Chromium 1194, headless, viewport **1600×1000**, `deviceScaleFactor: 1`, loaded from `file:///root/qa/grounds-v0.html`.
`page.on("pageerror")` and `page.on("console")` (type=error) plus `requestfailed` were attached **before** `goto` and kept for the whole run. ## BUGS (most severe first)

**B1 [blocker] [attention cycle / quest addressing] — a timed quest addressed to the Quest Board crashes "⚑ What needs hands"**

   Steps:
   1. ⚒ Build → click the **Greenhouse & Gardens** icon (world 1351,549) → inspect card opens.
   2. Under *quests here*, set the address dropdown for **"Plant the dry-season beds"** (`SCENE.quests[0]`, need = "2 more hands · Thu") to **"Quest Board — unaddressed"**. Toast confirms; `quest.at` becomes `null`.
   3. Close the inspect card, leave build mode.
   4. Click **⚑ What needs hands** (or press Space) repeatedly. The cycle walks the 8 seats first, so the crash lands on **click #9**.

   Expected: the cycle skips (or gracefully handles) work that has no address on the map; no errors.
   Actual: uncaught TypeError, the attention card never renders, and the cycle is stuck on that index — every further click re-throws.
   ```
   pageerror: Cannot read properties of undefined (reading 'x')
       at $.onclick (file:///root/qa/grounds-v0.html:1376:14)
   ```
   Line 1376 is `travelTo(s.x,s.y,1.3);` in `$('attnBtn').onclick`, where `const s=BY[it.at]` is `undefined` because `attnItems()` still includes board-bound quests (`it.at === null`). The badge also keeps counting it (stayed at 12), so the count promises an item the UI cannot open.
   Screenshot: `24c-attention-board-quest.png`. **This is the only error captured all session (see §27).**

**B2 [major] [tour] — panning during a camera leg kills the tour permanently**

   Steps: click **Take the tour** → wait ~420 ms (stop 0's flight is still in progress, `travel === true`) → press and drag on bare land (e.g. grab at 300,780 → 190,840) → release.
   Expected (§14): "pan mid-tour safe" — you wander off, the tour continues.
   Actual: the tour dies silently and never resumes. `tourI` stays at **0** for the full 25 s observation window; the log holds only "Come — the short walk…" (stop 0's narration never fires, and no stop advances). Reproduced 3× (twice in a dedicated repro session, once in the main run).
   Cause: `cv`'s `pointerdown` sets `travel = null`, which discards the `done` callback that both narrates and schedules `nextTour`. Nothing re-arms the chain.
   Screenshot: `14b-tour-after-pan.png`. Contrast `14a-tour-end.png` — undisturbed, all 8 stops narrate and the camera flies each (t=0/7/13/19/25/31/37/43 s), ending on the invitation.

**B3 [major] [keyboard / build mode] — closing the inspect card traps focus and kills every global hotkey, including Ctrl+Z**

   Steps: ⚒ Build → click any palette item (e.g. **Sauna**) → click inside the property line to place it (the inspect card auto-opens) → click the card's **✕** → press **Ctrl+Z**.
   Expected (§17): Ctrl+Z undoes the add.
   Actual: nothing happens. `document.activeElement` is still `#inspClose`, which lives inside `#inspect`; that element's keydown listener calls `e.stopPropagation()` unconditionally, so the window-level handler never sees the key. Measured before/after: `{n:23, undo:1}` → `{n:23, undo:1}`. **W, H, V, T, Space and the arrow keys are dead the same way** (W: wall `false → false`). Clicking bare land moves focus to `BODY` and everything works again (`{undo:1} → {undo:0}`, structure removed). The ↩ Undo button always works.
   This lands on the single most common build path — place → the card opens itself → close it → undo — so Ctrl+Z is unreachable exactly when you want it. Reproduced in the main run and in a dedicated repro session.

**B4 [major] [camera] — black beyond the map edges during minimap travel (the interpolation is never clamped)**

   Steps: set the camera to (1900,1250) @ z=1.6, then click the **top-left corner of the minimap** (3 px inside).
   Expected (§2): "Never black beyond map edges."
   Actual: `travelTo` receives the raw click target (world 0,0) and `frame()` interpolates straight toward it, calling `clampCam()` **only when `travel.t >= 1`**. Frame-accurate capture: the worst rendered frame sits at **cam (30,30) @ z=1.6 — 470 world units past the clamp limit of (500,312.5)**, filling roughly **47 % of the 1600×1000 viewport with the void colour `#101d13`**, then snapping back. In the main-run instrumentation 5 of 8 sampled screen corners were off-map for ~300 ms (cam walked 382,266 → 189,137 → 84,66 → 45,40 → 31,31 before the snap).
   Screenshot: **`B-blackedge-midtravel-frame.png`** (canvas grabbed inside the offending rAF frame). Timeline in the log under "§5 mid-travel edge probe".
   Note: settled positions are always clamped correctly, and drag/wheel/keys/H never produced an off-map corner — this is specific to `travelTo` targets that are outside the legal camera box (minimap edge clicks are the easy repro).
